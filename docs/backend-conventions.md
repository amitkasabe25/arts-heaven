# Backend conventions (apps/api)

## Response contract

Controllers return either plain data (auto-wrapped by `ResponseInterceptor` as
`{ success, message, data }`) or `{ data, meta }` for paginated results (wrapped with `meta`).
Use `@ApiMessage('...')` for a meaningful message. Errors throw Nest `HttpException`s and are
normalised by `AllExceptionsFilter` into `{ success: false, message, data: null, errors?, code? }`.

## Module pattern

```
src/<module>/
  dto/*.dto.ts
  <module>.service.ts     # business logic
  <module>.controller.ts  # thin, DTO + decorators only
  <module>.module.ts
```

- Controllers never touch `PrismaService` directly.
- All writes that touch money or stock run inside `prisma.$transaction`.
- Use `PrismaService` (global), `RedisService` (global), queue tokens
  (`NOTIFICATION_QUEUE`, `INVENTORY_QUEUE`) from the global `QueueModule`.
- Use `@UseGuards(JwtAuthGuard)` + `@Roles(...)`/`@Permissions(...)` on admin endpoints.
- Use `PaginationQueryDto`, `skipTake()`, `paginationMeta()` for lists.
- Use `Prisma.Decimal` for money via `decimal()/add()/subtract()/number()` from
  `common/utils/money.util.ts`. Never accept client-provided prices.

## Customization contract

`CustomizationService` (module `src/product-customization`) exposes:

```ts
validateAndPrice(
  definitions: Array<{ key: string; type: CustomizationFieldType; label: string;
    isRequired: boolean; options: unknown; validation: unknown; priceDelta: Prisma.Decimal }>,
  values: Array<{ fieldKey: string; value: unknown }>,
  uploadedAssetIds: string[],
): Promise<{ values: Array<{ fieldKey: string; value: unknown; label?: string }>;
            extra: Prisma.Decimal; assetIds: string[] }>
```

Shopping and checkout must call this before computing prices; a failed validation throws `BadRequestException`.

## Guest identity

Guest clients send `X-Guest-Token` (a UUID generated by the client) on cart requests.
Authenticated clients use the bearer token. On login, `POST cart/merge` merges the guest cart into
the user cart. Guest tokens are never used for orders containing payments without an email/phone.

## Idempotency

Mutation endpoints that create money movement (`checkout/place`, `payments/create`, refunds) accept
`X-Idempotency-Key`. Replays with the same key and payload return the original result.
